# frontend-engineering — provenance

Synthèse éditoriale issue de la recherche relue du 7 septembre 2026. Les procédures des phases sont notre traduction dans le contrat v1, pas une certification des organismes cités. Vérifier la version et l’applicabilité d’une norme ou documentation évolutive avant d’en tirer une exigence actuelle.

- [Web Content Accessibility Guidelines (WCAG) 2.2](https://www.w3.org/TR/wcag/) — W3C, principes, critères testables, niveaux et évaluation automatisée plus humaine.
- [ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/) — W3C, motifs de widgets, rôles, états, noms accessibles et clavier.
- [Core Web Vitals](https://developers.google.com/search/docs/appearance/core-web-vitals) — Google Search Central, LCP/INP/CLS, seuils et mesure issue d’utilisateurs réels.
- [Progressive enhancement](https://developer.mozilla.org/en-US/docs/Glossary/Progressive_Enhancement) — MDN Web Docs, base fonctionnelle puis enrichissement selon les capacités.

Les statuts, étapes et critères d’intégration sont une synthèse pour le Spec Workflow ; les sources décrivent des pratiques ou standards situés et ne prescrivent pas ce contrat.
