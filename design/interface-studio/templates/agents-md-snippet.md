## Frontend craft

Use `interface-studio` for a new/material interface or a request spanning design disciplines. Route targeted copy, direction, system, motion, or QA work directly to the matching specialist and shortest safe mode.

- An explicit bounded request authorizes its named local design/frontend edits. Ask again only when scope/effect expands, a material choice needs the human, or the next action adds a dependency, touches live/external/production state, is destructive, or deploys/publishes.
- If route/copy/design judgment is explicitly delegated, select, record the rationale, and continue without a second approval.
- Generate only enough references, copy routes, visual directions, states, viewports, and correction passes to resolve the real decision and support the completion claim. One direction is valid when constraints already select it.
- Inherit and extend the canonical existing UI system for bounded work. A consequential new system choice needs delegated or human selection; proposal-only work does not imply build authority.
- Interface Studio owns story/copy, visual direction, system decisions, motion, and visual QA. Route behavior/production concerns once—through `software-engineering` when installed and materially useful, otherwise directly to the applicable website/web-app/dashboard engineering specialist. Do not require both or replay discovery.
- Inline briefs/options/claims/motion/review notes are valid. Persist them only when requested, needed across runs/agents, or required by the project.
- Critique rendered work before automated output when visual quality is in scope, then run affected browser/accessibility/runtime probes. A screenshot or tool `PASS` proves only its bounded claim.
- Stop revision on acceptance, diminishing returns, a blocker/choice, the agreed budget, or a scope boundary; report residual material findings.
- Real-time graphics are strictly opt-in by explicit request or named product need. Semantic DOM and usable fallback are default; preserve reduced motion/data, loss handling, offscreen pause, cleanup, performance/capture truth, and dependency authority. Route framework APIs to official relevant skills/docs.
- Never infer authority for unsupported claims, dependency changes, destructive/live effects, production data, deployment, publication, DNS, analytics, consent, or external accounts.

Existing stricter repository, security, data, and release rules still apply. A pre-existing `.design-flow/workflow.json` schema `1.0` is a project-local constraint: do not bypass, delete, reinitialize, or migrate it without explicit authority.
